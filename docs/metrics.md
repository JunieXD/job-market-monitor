# 指标口径

所有日度指标只使用 `daily_snapshots` 指向的标准快照，不读取 `jobs` 当前状态拼接历史。

## 公司岗位趋势

- `active_posting_count`：标准快照中去重后的公开岗位条目数。
- `new_posting_count`：第一次进入标准快照的岗位数；基线日固定为 0。
- `changed_posting_count`：本次标准快照发现内容变化的岗位数。
- 来源事实契约升级首次补齐的字段写为 `enriched` 审计事件，不属于市场指标，且不得并入
  `changed_posting_count`。
- `first_missing_posting_count`：本次标准快照第一次缺失的岗位数。
- `closed_posting_count`：本次标准快照确认关闭的岗位数。
- `reopened_posting_count`：本次标准快照重新出现的已关闭岗位数。

岗位条目数不等于招聘人数。一个岗位条目可能招聘多人，也可能没有实际录用。

趋势的时间轴优先使用每日标准快照的 `snapshot_date`。官网发布时间只能作为岗位自身的来源
事实展示，不能代替每日观测时间；阿里统一校园入口当前不提供发布时间，`source_updated_at`
也不能被解释为发布时间。项目首次基线只能表示“开始监测时已有”，不能反推此前何时新增。

## 类别占比

公司内部来源类别占比：

```text
该来源类别岗位数 / 同公司、同渠道、同日全部岗位数
```

跨公司类别占比只能使用当前发布的统一分类映射。尚未映射的岗位归入“未映射”，不能静默丢弃。
完全没有来源分类的岗位单列为“未分类”，不能与“已有来源分类但尚未统一映射”的“未映射”
混为一类。一个岗位可属于多个官网分类，因此分类占比之和可以超过 100%；页面必须同时展示
`direct_field` 或 `filter_membership` 证据口径。

## 城市分布

多城市岗位同时提供两种指标：

- `posting_count`：岗位与该城市有关联就计 1，适合回答“该城市涉及多少岗位”。各城市之和可能
  大于岗位总数。
- `fractional_posting_count`：一个岗位有 N 个城市时，每个城市计 `1/N`。各城市之和等于岗位
  总数，默认用于城市占比。

`fractional_share` 使用折算岗位数计算。跨公司城市榜还必须同时显示当天成功覆盖的公司数。

## 来源业务单元分布

阿里等来源若直接提供业务单元，按 `job_version_business_units` 关联统计：

- `business_unit_posting_count`：该标准快照中关联到该业务单元的去重岗位数。
- `business_unit_share`：业务单元岗位数 / 同来源、同渠道、同日全部岗位数。

一个岗位可以同时属于多个业务单元，因此各业务单元占比之和可能超过 100%；这不是重复采集，
而是来源本身的多归属事实。跨来源把两个业务单元合并前，必须另行发布带版本的组织映射，不能
仅凭名称相似自动合并。

## 尚未启用的主题趋势

当前没有正式主题体系，也不生成或发布主题指标。关键词搜索结果只能称为“文本搜索命中”，
不得展示为主题分类、岗位标签或市场趋势。

未来只有在主题定义、模型或标注方法、评估标准和版本发布流程全部确定后，才能新增主题分析
视图。届时主题首次出现仍必须区分官网首次发布时间和系统首次观测日期；系统开始监测以前的
真实市场变化不能从首个快照反推。

## 覆盖范围

任何跨公司“市场”指标都只代表已覆盖招聘官网的公开岗位。页面必须展示：

- 当天成功覆盖公司数
- 配置公司总数
- 各来源最近成功时间
- 采集是否完整
- 未映射分类或地点比例
