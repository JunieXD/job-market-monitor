# 数据源目录与统计边界

“公司”与“招聘网站来源”不是同一个概念。一个公司可以有多个招聘站；每个招聘站又可能
同时提供校招和社招。采集、生命周期和每日快照首先按 `source + channel` 隔离，只有在明确
去重规则后才做公司级聚合。

快手列表按更新时间变化频繁，长列表直接翻页会在采集期间发生相邻页重复。连接器使用官网

快手校园站不再依赖登录页面。连接器读取公开项目、类别、地点和岗位性质字典，动态选择最新的

百度连接器使用招聘官网公开的 `getPostListNew` 表单接口，按接口固定的 10 条页大小完整翻页。

滴滴社会招聘列表和详情均可在官网匿名页面上下文中读取。列表约六十余页且采集期间实时变化，

哔哩哔哩的应届全职和实习由官网 `type` 筛选明确分开。岗位对象提供类别名称，连接器同时保存

蚂蚁社招列表岗位对象已包含职责、要求和主要分析字段。岗位分类以官网随岗位返回的完整分类

360 社招列表由官网一次请求全部公开岗位，当前数量远低于 10,000 条上限；达到上限时连接器会

日期大量冲突，规范化发布时间采用详情页值，两份原始值均保留用于审计。

腾讯社会招聘站未筛选页面会混合社招、校招应届生和实习生。连接器通过官网控件明确选择“社招”，

当作完整性分区；岗位分类直接读取每条记录的 `CategoryName`。列表同时提供职责、城市、事业群、
经验和更新时间。当前为避免每天额外请求两千多个详情页，不采集详情独有的任职要求，该字段保持
`NULL`；官网 `CategoryName` 为空的岗位保持未分类，不从标题补齐。这与独立的腾讯校园招聘来源
分别计数。

小红书社招按官网六个互斥一级类别分区，避免按发布日期变化的长列表在翻页时遗漏岗位。岗位对象

爱奇艺列表直接提供职责、要求、稳定岗位 ID、岗位编码、两级职能分类、城市代码、招聘性质、

米哈游列表只返回岗位摘要，连接器使用官网公开的 100 条页大小完整遍历，再通过同一匿名浏览器

虎扑使用智业公开接口的 `Count` 和 `Data`，`Total` 不作为总数依据。连接器将页大小设为 1000，

## 已调查但未接入

- 滴滴校园招聘：匿名职位页面可见，但 Moka 岗位接口的业务载荷采用站点内部加密协议。项目不
  复制易失的解密实现，也不使用登录态或绕过访问控制；在出现稳定、明确的公开数据协议前保持
  未接入。滴滴社会招聘不受此限制，已作为独立来源接入。
- 大疆、唯品会、新浪、搜狐、58 同城、金山办公和完美世界当前招聘入口同样使用 Moka 加密业务
  载荷。本轮未复制其站内解密逻辑，也未把页面展示数量冒充完整岗位集合；出现稳定公开协议后再
  评估接入。
- 4399 社会招聘页可以直接读取全文，但页面和岗位内容长期未更新，仍包含明显过时的 AS3/Flex
  岗位与 2014 年页面信息，因此不作为当前活跃就业市场的权威来源。

## 计数和去重

1. 来源内：以该站的 `source + external_id` 计一个岗位；一个岗位有多个城市仍只计一个岗位，
   城市关系单独展开。
2. 来源间：先保留各站独立计数。只有发现同一岗位跨站展示，才用来源链接、外部编码、标题、
   描述和地点等证据建立重复审计记录。
3. 公司级：默认展示“来源岗位数”和“去重后岗位数”两个口径，不把未经审计的来源简单求和。
4. 历史趋势：使用每日完整快照的观测日期；官网岗位总数和招聘人数不是同一个指标。

## 目前观测到的数量为什么不同

历史调查中，阿里校园、淘天社招和字节校园的数量相差很大。它们的批次周期、业务覆盖、岗位
拆分和官网统计口径不同，且都只是岗位条目数，
不能解读为招聘人数或集团总岗位数。数量随官网实时变化，报告必须同时记录来源、渠道和快照日期。
